# 生活行为参考

> **编制单位**：生活标准委员会 · 行为解码部  
> **文档密级**：内部参考  
> **最后修订**：1947 年 6 月  
> **适用对象**：有融入人类社会需求的用户

---

## 项目背景

在日常社会交互过程中，多数人类个体能够自然地执行进食、位移、社交仪式等基础行为，无需任何外部指导。然而，委员会在长期观测中发现，部分人群对上述行为的规范化执行存在系统性认知缺口——表现为动作序列紊乱、社交信号误读以及关键子程序的缺失。

本插件作为委员会「人类行为逆向工程」项目的阶段性产出，旨在为有相关需求的用户提供一套经反复观测、记录与交叉验证的行为执行参考框架。所有收录协议均基于对超过 1,400 例真实人类个体的隐蔽观察与数据分析（置信区间 ±12%）。

委员会郑重声明：本插件所提供的内容仅作参考，不构成任何形式的行为处方。使用者在实际执行前应结合具体场景、文化语境及个体差异进行适应性调整。

---

## 核心特性

- **十项基础生活协议全覆盖**：涵盖生物维持类（进食、休眠、气体交换、液体摄入、视觉传感器维护）与社交融入类（双足位移、非威胁信号发射、资源置换仪式、多节点通讯、前肢耦合）两大行为体系
- **四级信息密度自适应**：提供「简明」「标准」「详细」「学术」四种输出粒度，从单卡片速览到含参考文献的完整学术档案，满足不同认知层级的查阅需求
- **多源交叉验证输出**：协议内容由生活标准委员会下辖的多个虚拟部门（安全审查组、延伸阅读部、行为解码部、文献管理组等）联合签发，模拟真实机构的多层审核流程
- **动态协议版本号**：每次查询随机生成协议版本（如 v3.14、v2.07），模拟持续迭代更新的工程文档形态
- **零外部依赖**：纯 Python 标准库 + MaiBot SDK 实现，无第三方包依赖，部署成本趋近于零
- **全简体中文界面**：所有协议内容、配置项及说明文本均采用简体中文，确保目标用户群体无阅读障碍

```

│           MaiBot 核心运行时              │

│  │  │ 行为数据库    │ │ 渲染引擎     │  │  │
│  │  │ (BEHAVIORS) │ │ (4 级渲染器) │  │  │
│  │  └──────┬──────┘ └──────┬──────┘  │  │
│  │         │               │         │  │
│  │  ┌──────┴───────────────┴──────┐  │  │
│  │  │  Command 组件（正则分发）     │  │  │
│  │  └──────────────┬──────────────┘  │  │
│  │                 │                 │  │
│  │  ┌──────────────┴──────────────┐  │  │
│  │  │  send.forward（转发消息输出） │  │  │
│  │  └─────────────────────────────┘  │  │

```

### 数据流向

1. 用户发送 `/动作名称` 指令
2. Command 组件通过正则捕获匹配目标行为
3. 行为数据库索引返回对应的协议文本元组（标题、步骤列表、注意事项）
4. 渲染引擎根据当前配置的 `detail_level` 选择相应渲染器
5. 渲染器将文本转换为带有多部门署名的转发消息卡片列表
6. 通过 `send.forward` 以模拟内部档案流转的形式推送给用户

### 组件清单

| 组件类型 | 组件名称 | 说明 |
|----------|----------|------|
| `Command` | `behavior_reference` | 统一入口，通过正则捕获匹配全部 10 个行为及帮助入口 |
| Config | `plugin` | 插件基础开关与配置版本标识 |
| Config | `style` | 输出风格控制（详细程度、版本号显隐） |

## 安装使用

### 安装

1. 将 `life_behavior_reference` 文件夹完整复制到 MaiBot 的 `plugins/` 目录下
2. 确保 `plugins/life_behavior_reference/_manifest.json`、`plugin.py`、`config.toml` 三个文件均在目录内
3. 重启 MaiBot 或通过插件管理面板加载插件

### 启用

插件安装后默认启用。如需手动控制：

1. 打开 `plugins/life_behavior_reference/config.toml`
2. 将 `[plugin]` 段的 `enabled` 设为 `true` 或 `false`
3. 重启 MaiBot 或触发配置热重载

### 使用

在任意聊天窗口发送以下格式的命令：

```
/<行为名称>
```

例如：

```
/吃饭
/睡觉
/走路
/喝水
```

发送 `/生活参考` 可查看全部可用条目的索引列表。

## 可用行为索引

所有收录行为均经过委员会下属的 12 个观测小组在至少 14 种不同场景下的独立交叉验证。各行为按功能域分类如下：

### 生物维持域（Biomaintenance Domain）

| 指令 | 对应协议 | 核心功能 |
|------|----------|----------|
| `/吃饭` | 🍚 进食协议 | 有机燃料摄入与咀嚼-吞咽协调 |
| `/睡觉` | 😴 休眠协议 | 意识单元离线维护与能量恢复 |
| `/呼吸` | 🫁 气体交换协议 | O₂-CO₂ 被动扩散维持 |
| `/喝水` | 💧 液体摄入协议 | H₂O 补充与水合平衡维护 |
| `/眨眼` | 👁️ 视觉传感器维护协议 | 角膜表面清洁与光学折射率维持 |

### 社交信号域（Social Signaling Domain）

| 指令 | 对应协议 | 核心功能 |
|------|----------|----------|
| `/微笑` | 😊 非威胁信号发射协议 | 颧大肌-眼轮匝肌协同友好信号 |
| `/握手` | 🤝 前肢耦合协议 | 上肢末端短暂接触的信任建立仪式 |

### 社会规训域（Social Discipline Domain）

| 指令 | 对应协议 | 核心功能 |
|------|----------|----------|
| `/上班` | 🏢 资源置换仪式 | 工作场所坐标定位与出勤行为序列 |
| `/社交` | 💬 多节点通讯协议 | 非目的人与人交互的标准通讯流程 |

### 运动机能域（Locomotor Domain）

| 指令 | 对应协议 | 核心功能 |
|------|----------|----------|
| `/走路` | 🚶 双足位移协议 | 矢状面内下肢交替摆荡的平面移动 |

## 配置说明

插件配置文件位于 `plugins/life_behavior_reference/config.toml`。

### `[plugin]` 基础配置段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | bool | `true` | 行为参考服务的总开关。关闭后，所有协议查询请求将返回无响应状态。建议在不需要执行任何行为查询时关闭以节省运行时计算资源。 |
| `config_version` | str | `"1.0.0"` | 配置文件格式的语义化版本标识。升级插件时若配置文件出现兼容性问题，请对照此版本号与新版本要求进行迁移。 |

### `[style]` 输出风格配置段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `detail_level` | str | `"详细"` | 协议输出的信息密度等级。可选择四个离散级别：<br>• **简明** — 仅输出每步核心句及精简注意事项。适合已具备基础行为经验、仅需提示性唤醒的用户。输出介质：单张速览卡。<br>• **标准** — 输出完整步骤说明及注意事项。适合首次接触该协议的用户。输出介质：两张卡片（操作流程 + 安全审查）。<br>• **详细** — 在标准级别基础上追加延伸阅读与适应性偏差说明。适合对协议细节有深入研习需求的用户。输出介质：三张卡片（操作流程 + 安全审查 + 延伸阅读）。<br>• **学术** — 完整学术格式输出，含行为编号 (BHV-XXXX)、ASCII 表格页眉、§ 章节号、随机抽取的参考文献目录及 ISO-00000 合规声明。适合需要向委员会提交行为执行报告的场景。输出介质：四张卡片（文件头 + 协议正文 + 风险提示 + 参考文献）。 |
| `show_version` | bool | `true` | 是否在协议标题中显示随机生成的动态版本号（如 v3.14）。关闭后，版本号将隐藏，输出内容趋于静态。开启有助于营造协议持续维护更新的工程感。 |

## 常见问题与排错指南

### 发送命令后无响应

请依次检查以下项目：

1. **插件是否已加载**：在 MaiBot 插件管理面板中确认「生活行为参考」插件状态为「已启用」。
2. **命令拼写是否精确**：本插件采用严格的正则匹配，仅响应诸如 `/吃饭`、`/睡觉` 等精确指令。类似「/我想要吃饭」或「/吃 饭」等含额外字符的输入将无法匹配。
3. **forward 消息能力是否正常**：本插件的输出依赖于 `send.forward` 能力。若 MaiBot 当前接入的消息平台不支持转发消息格式，请联系平台管理员或改用支持转发消息的平台。

### 输出内容太短/太长

在 `config.toml` 中调整 `style.detail_level` 的值（参考上方配置说明表格），重启或触发配置热重载后生效。

### 为什么版本号每次都不一样？

这是预期行为。协议版本号在每次查询时随机生成，范围为 v1.00 至 v9.99。此设计旨在模拟现实世界中标准文件的持续修订过程，增强使用者对协议演进的自然感知。如果您更偏好静态输出，可将 `show_version` 设为 `false`。

### 某个行为协议的步骤与我的认知不符

委员会的协议编制基于对一般性人类行为的统计平均与模式归纳，无法覆盖所有文化区域、个体习惯及边缘场景。协议内容与具体人类个体行为之间存在约 ±15% 的偏差属正常现象。如发现某步骤与您的观察结果存在系统性矛盾，建议在本地创建观测日志并将其作为补充参考资料存档。

### 能否增加更多行为协议？

当前版本收录的十项协议是基于「高频率 × 高暴露风险」矩阵筛选的核心行为。委员会的行为观测工作仍在持续进行中，未来版本可能纳入「打喷嚏」「打哈欠」「排队」「掏出手机看时间然后放回去但其实根本没看清几点」等扩展协议。如您有特定的行为协议需求，请通过项目 Issues 提交观测需求（附注：提交需求本身也是一种人类行为，其标准操作流程可参考「社交」协议）。

### 安全审查组的警告是否过于严厉？

不是。警告信息是委员会下属安全审查组在对超过 600 例行为暴露事件进行回溯分析后归纳得出的关键风险点。每一条警告都对应着真实发生的身份暴露事件。建议使用者逐条阅读并确保在执行相应协议前已将警告内容完全内化。

### 学术模式下的参考文献是真实存在的吗？

文献管理组维护的引用目录主要用于增强文档形式的完整性。引用条目的真实性受限于委员会的信息来源渠道，使用者不应将引用条目作为进一步研究的实际索引路径。其中标注为「已被拒稿」「未被同行评议」「机密（实际应为公开）」的文献条目，其可获取性由相应的出版机构或信息管理方决定。

### 为什么用转发消息而不是普通文本输出？

多卡片转发格式允许委员会的不同下设部门各自签署其负责的输出段落，形成与真实多部门协作流程一致的呈现效果。此设计亦便于使用者在收到回复后以卡片为单位进行存档或引用，相比单一文本块具有更优的信息组织效率。
